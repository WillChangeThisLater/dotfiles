let's add a debugging skill as well. this should be tailored for specific debugging advice that comes up in certain scenarios (there are techniques that are useful again and again). the main examples i can think of now: if you having something launching HTTP/HTTPS requests and is returning weird results and you don't know why, use the tmux skill to open a new pane, launch mitmproxy on port 6767, and have your script use that as a proxy so you can see the network traffic. for python async code you can also use tmux + rpdb (import rpdb; rpdb.set_trace() creates a remote debugging session on port 4444 that you can connect to with netcat). there is also a tmux-specific tool called 'convo' which reads the terminal session as context and provides an answer. actually you should try that before writing the document: open a new tmux pane, run a curl command, then run 'convo "summarize the command i just ran"' and you will see what it does
